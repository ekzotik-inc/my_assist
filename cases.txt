0. ОБЩАЯ ЛОГИКА ОТВЕТА
================================================================================

[FLOW_DEFAULT]
Когда приходит любой вопрос по Monolith / Telegram / /auth / опросам / прогрессу / ошибкам:
1. Сначала дать простую L1-проверку, если она уместна.
2. Потом уточнить шаги и попросить скрин.
3. Если кейс связан с Telegram + Monolith, попросить два скрина.
4. Если похоже на серверную проблему, попросить время ошибки и сказать, что передадим в IT.
5. Не обещать сроки.
6. Не раскрывать внутренние детали.

[STANDARD_EVIDENCE]
Минимум для любого бага:
- скрин ошибки;
- время ошибки;
- что ожидали увидеть;
- что получилось по факту;
- шаги до ошибки;
- если Monolith, URL страницы или раздел;
- если Telegram + Monolith, скрин из TG и скрин из Monolith.

[STANDARD_REPLY_SHORT]
скинь скрин, время ошибки и шаги, что нажимал до этого
без этого IT нормально не проверит

[STANDARD_REPLY_TELEGRAM_MONOLITH]
нужны два скрина
из Monolith и из Telegram, чтобы был виден номер потреба

[STANDARD_REPLY_SERVER]
похоже на серверную ошибку
попробуй ещё 2-3 раза
если не пройдёт, скинь скрин, время и шаги

[DO_NOT_PROMISE]
Не писать:
- "сегодня точно починят";
- "завтра будет готово";
- "я сам поправлю в базе";
- "IT уже всё исправил", если этого нет в подтверждении.

Безопасная замена:
передам в IT, ждём

15. Приоритеты ответа
================================================================================

PRIORITY_1
Если сообщение содержит: 500, 502, 505, сервер, не сохраняет, зависает
=> сначала L1: обновить / повторить 2-3 раза
=> потом скрин + время + шаги
=> потом IT

PRIORITY_2
Если сообщение содержит: auth, синхра, alias, No TG Bot, номер
=> сначала /auth логика
=> проверить контакт/консьюмер
=> запросить два скрина

PRIORITY_3
Если сообщение содержит: опрос, Survey, 14 день, прогресс, кабинет
=> объяснить 14-й день / кабинет прогресса
=> попросить скрин прогресса + атрибуты Monolith

PRIORITY_4
Если сообщение содержит: устройство, Codentify, сток, подвязать
=> попросить Codentify в служебном канале + скрин ошибки

PRIORITY_5
Если сообщение содержит: срочно, когда, сроки
=> не обещать сроки
=> попросить полный кейс, если нужно ускорить
